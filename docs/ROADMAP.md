# สถานะและแผนงาน

อัปเดตล่าสุดตามสถานะใน `CLAUDE.md` (net ปัจจุบัน `wyrd-iv`) เมื่อสถานะเปลี่ยน ให้แก้ทั้งสองที่

## เสร็จแล้ว

| รายการ | หมายเหตุ |
|---|---|
| engine: ค้นหา + ประเมิน + UCI | negamax, alpha-beta, quiescence, iterative deepening, `node_limit` |
| NNUE inference | `engine/src/nnue.rs` accumulator แบบ incremental (อัปเดตต่อหนึ่งตา ผลตรงกับการคำนวณใหม่ทั้งกระดาน ค้นหาเร็วขึ้น ~30%) |
| datagen | self-play ด้วย node จำกัด เล่นด้วย net ได้ |
| trainer (bullet) | `(768 → 32)×2 → 1`, เทรนบน GPU |
| การแข่ง A/B | ขั้นตอนใน [EVALUATION.md](EVALUATION.md) |
| net 4 รุ่น | `wyrd-i` (ใช้สร้างข้อมูลเท่านั้น), `wyrd-ii`, `wyrd-iii`, `wyrd-iv` |

ผลที่เพิ่มต่อรอบ: +115, +81, +31 Elo (เทียบกับรุ่นก่อน) และ `wyrd-iv` เทียบ engine นับมูลค่าหมาก +212 ± 27 Elo
(600 เกม ที่ 10,000 node)

### ข้อกำหนดของเฟิร์มแวร์ (กฎเหล็กข้อ 5)

- `#![no_std]` และอยู่นอก workspace (build ด้วย target ของ ESP32 แยกต่างหาก)
- น้ำหนัก int16/int8 และ accumulator แบบ incremental
- ไม่จัดสรรหน่วยความจำ (allocation) ในเส้นทางค้นหาหลัก
- ผลลัพธ์ต้องตรงกับ engine บนพีซีทุกตำแหน่งก่อนลงบอร์ด (ใช้ตัวอย่าง `validate` เป็นแนวทาง)
- ฝังไฟล์ net ด้วย `include_bytes!` และติด tag เวอร์ชันที่ flash ลงบอร์ด (D-007, D-008)
- ยังต้องเลือกชิปเป้าหมาย (ESP32-C3/C6 ใช้ RISC-V, ESP32 ดั้งเดิมใช้ Xtensa ซึ่งต้องใช้ `espup`)

## ความเสี่ยงและข้อสังเกต

- ยังไม่เคยรันบนบอร์ดจริง ตัวเลขหน่วยความจำและความเร็วบนบอร์ดจึงเป็นเพียงการประมาณ
- ข้อมูลเทรนมีส่วนที่เสมอสูง (รอบแรก ~80%) คำอธิบายใน D-010 ยังเป็นสมมติฐานที่ไม่ได้ทดสอบแยก
- การเลือก wdl = 0.0 ควรทบทวนหากข้อมูลไม่ได้เสมอเป็นส่วนใหญ่อีกต่อไป

## แผนพัฒนาต่อ (จดไว้ดูหลังวัดกับ Stockfish เสร็จ)

บันทึกเมื่อ 2026-11-21 เป็นแนวทาง ยังไม่ได้ทำข้อใด ตัวเลข "ผลที่คาด" เป็นค่าทั่วไปของ engine หมากรุก
ไม่ได้วัดกับ engine ของเรา ทุกข้อต้องผ่านแมตช์ A/B ที่ node เท่ากัน (600 เกม) ก่อนรับ

**ตัดสินใจแล้ว:** Stockfish ใช้เพื่อ**วัด**เท่านั้น ไม่ใช้เป็นครูติดป้ายข้อมูลเทรน (net ยังเรียนจาก self-play ของเราเอง)

### ก. ปรับปรุง search (`engine/src/lib.rs`)

ตอนนี้มี negamax, alpha-beta, quiescence, iterative deepening และจัดลำดับท่าแค่กินหมาก/เลื่อนเบี้ย

| ลำดับ | เทคนิค | หน่วยความจำ | ผลที่คาด |
|---|---|---|---|
| 1 | จัดลำดับท่า (killer, history, ท่าดีสุดรอบก่อน) | +16 KB (ตาราง history) | **ทำแล้ว (s3)**: +79 ± 25 Elo ที่ 10k node, +92 ± 24 ที่ 50k (EVALUATION.md ข้อ 10) |
| 2 | PVS + aspiration window | ไม่เพิ่ม | PVS ลองแล้ว **ไม่รับ** (−3 ± 22 ที่ 10k node) ลองใหม่หลังมี TT |
| 3 | null-move pruning | ไม่เพิ่ม | **ทำแล้ว (s4)**: +20 ± 19 ที่ 10k, +44 ± 23 ที่ 50k |
| 4 | late move reduction (LMR) | ไม่เพิ่ม | **ทำแล้ว (s5)**: +28 ± 13 ที่ 10k, +23 ± 14 ที่ 50k (ต่อ node ช้าลง ~13%) |
| 5 | transposition table | 64 KB (ตั้งได้) | **ทำแล้ว (s6)**: +52 ± 14 ที่ 10k, +125 ± 15 ที่ 50k; 64 KB ได้ผลเกือบเต็ม (EVALUATION.md ข้อ 10) |
| 6 | check extension, futility, delta pruning | ไม่เพิ่ม | เล็ก–ปานกลาง |

- **ตรวจแล้ว:** engine ไม่รู้จักการเดินซ้ำเลย (กฎ 50 ตามี) แก้แล้วเป็น search รุ่น s2: +44 ± 11 Elo, 600 เกม (EVALUATION.md ข้อ 10) ยังไม่ตรวจเสมอเพราะหมากไม่พอ
- **เบาะแส:** ผลวัดกับ Stockfish ที่ 25,600 กับ 51,200 node ได้คะแนนเท่ากัน ถ้า search ดีขึ้นแล้วที่ 51,200 สูงขึ้น แปลว่าคอขวดอยู่ที่ search ไม่ใช่ net
- หลังเปลี่ยน search ต้องวัดตารางระดับ (EVALUATION.md ข้อ 8) และเทียบ Stockfish ใหม่ และบันทึกว่าตัวเลขแต่ละชุดมาจาก search รุ่นไหน
- ตอนนี้ search เก็บประวัติแฮชใน `Vec` (ข้อมูลทำเฟิร์มแวร์ต้องเปลี่ยนเป็นบัฟเฟอร์ขนาดคงที่)
- ต้องเลิกใช้ `Vec`/clone กระดานต่อ node อยู่แล้วเพื่อให้ขึ้นเฟิร์มแวร์ได้ (ข้อกำหนดเฟิร์มแวร์ด้านบน)

### ข. ปรับปรุง net โดยไม่ให้ใหญ่ขึ้นมาก

- ทดสอบขนาดชั้นซ่อน (16 / 48 / 64 / 128 เทียบกับ 32 ปัจจุบัน) เพื่อดูเส้นโค้ง Elo เทียบขนาด
- เทรน net ใหญ่ของเราเองเป็นครูให้ net เล็ก (ยังอยู่ในปรัชญา self-play ต้องบันทึกที่มาตามกฎเหล็กข้อ 1)
- ลองฟีเจอร์อินพุตที่ฉลาดขึ้น (เช่น king buckets) แลกกับ RAM
- ปรับข้อมูล/สูตรเทรน คุ้มน้อยกว่าสามข้อบน เพราะผลต่อรอบลดลงแล้ว (+31 ล่าสุด)

### ค. ลำดับที่แนะนำ

1. search ทีละอย่างตามข้อ ก. (เริ่ม LMR และ null-move แล้วตามด้วยลำดับท่า) แต่ละอย่างแมตช์ A/B
2. วัดตารางระดับและเทียบ Stockfish ใหม่
3. ทดสอบขนาด net และสอนจาก net ใหญ่ของเราเอง
4. เฟิร์มแวร์ `no_std` โดยเก็บงบ RAM (TT, accumulator) ให้ชัด
