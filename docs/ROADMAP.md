# สถานะและแผนงาน

อัปเดตล่าสุดตามสถานะใน `CLAUDE.md` (net ปัจจุบัน `wyrd-iv`) เมื่อสถานะเปลี่ยน ให้แก้ทั้งสองที่

## เสร็จแล้ว

| รายการ | หมายเหตุ |
|---|---|
| engine: ค้นหา + ประเมิน + UCI | negamax, alpha-beta, quiescence, iterative deepening, `node_limit` |
| NNUE inference | `engine/src/nnue.rs` accumulator แบบ incremental (อัปเดตต่อหนึ่งตา ผลตรงกับการคำนวณใหม่ทั้งกระดาน ค้นหาเร็วขึ้น ~30%) |
| datagen | self-play ด้วย node จำกัด เล่นด้วย net ได้ |
| trainer (bullet) | `(768 → 32)×2 → 1`, เทรนบน GPU |
| การแข่ง A/B | ขั้นตอนใน [EVALUATION.md](EVALUATION.md) |
| net 4 รุ่น | `wyrd-i` (ใช้สร้างข้อมูลเท่านั้น), `wyrd-ii`, `wyrd-iii`, `wyrd-iv` |

ผลที่เพิ่มต่อรอบ: +115, +81, +31 Elo (เทียบกับรุ่นก่อน) และ `wyrd-iv` เทียบ engine นับมูลค่าหมาก +212 ± 27 Elo
(600 เกม ที่ 10,000 node)

## งานที่เหลือ

เรียงตามลำดับที่แนะนำ

| ลำดับ | งาน | สถานะ | หมายเหตุ |
|---|---|---|---|
| 1 | เทรนรอบที่ 5 | ไม่บังคับ | ผลที่เพิ่มต่อรอบลดลง อาจใกล้ถึงเพดานของ net ขนาดนี้ |
| 2 | ระดับความแรงที่วัดเป็น Elo | ยังไม่เริ่ม | แมปค่า `Nodes` (และความสุ่ม) เป็น Elo เพื่อให้ผู้ใช้เลือกระดับได้ |
| 3 | เทียบกับ engine ภายนอก | ยังไม่เริ่ม | จำเป็นต่อการอ้างความแรงสัมบูรณ์ |
| 4 | NNUE แบบ incremental | เสร็จ (บนพีซี) | ยังต้องทำซ้ำแบบไม่จัดสรรหน่วยความจำใน `no_std` |
| 5 | เฟิร์มแวร์ `no_std` | โครงเปล่า | ดูข้อกำหนดด้านล่าง |

### ข้อกำหนดของเฟิร์มแวร์ (กฎเหล็กข้อ 5)

- `#![no_std]` และอยู่นอก workspace (build ด้วย target ของ ESP32 แยกต่างหาก)
- น้ำหนัก int16/int8 และ accumulator แบบ incremental
- ไม่จัดสรรหน่วยความจำ (allocation) ในเส้นทางค้นหาหลัก
- ผลลัพธ์ต้องตรงกับ engine บนพีซีทุกตำแหน่งก่อนลงบอร์ด (ใช้ตัวอย่าง `validate` เป็นแนวทาง)
- ฝังไฟล์ net ด้วย `include_bytes!` และติด tag เวอร์ชันที่ flash ลงบอร์ด (D-007, D-008)
- ยังต้องเลือกชิปเป้าหมาย (ESP32-C3/C6 ใช้ RISC-V, ESP32 ดั้งเดิมใช้ Xtensa ซึ่งต้องใช้ `espup`)

## ความเสี่ยงและข้อสังเกต

- ยังไม่เคยรันบนบอร์ดจริง ตัวเลขหน่วยความจำและความเร็วบนบอร์ดจึงเป็นเพียงการประมาณ
- ข้อมูลเทรนมีส่วนที่เสมอสูง (รอบแรก ~80%) คำอธิบายใน D-010 ยังเป็นสมมติฐานที่ไม่ได้ทดสอบแยก
- การเลือก wdl = 0.0 ควรทบทวนหากข้อมูลไม่ได้เสมอเป็นส่วนใหญ่อีกต่อไป
