# การเทรน NNUE ของ Wyrdmate (อ่านแล้วเข้าใจ)

เอกสารนี้อธิบายว่า Wyrdmate สร้าง "สมองประเมินตำแหน่ง" (NNUE) ขึ้นมาได้อย่างไร
ตั้งแต่ข้อมูลดิบจนถึงไฟล์ net เขียนให้คนอ่าน ไม่ต้องรู้เรื่อง AI มาก่อน

> **สถานะล่าสุด:** วงวนทำครบ 4 รอบแล้ว และ net ที่ผ่านการแข่งเก็บไว้ใน `nets/`
> (`wyrd-i` ถึง `wyrd-iv`) ตัวล่าสุด `wyrd-iv` ชนะ `wyrd-iii` **+31 ± 22 Elo** และชนะ
> engine นับมูลค่าหมาก **+212 ± 27 Elo** (600 เกมต่อคู่) ผลที่เพิ่มต่อรอบลดลงเรื่อยๆ (+115, +81, +31) รายละเอียดอยู่ที่
> [`nets/RECORDS.md`](../nets/RECORDS.md) และกราฟใน [`README.md`](../README.md)
> ผลทั้งหมดเทียบกับ engine รุ่นก่อนของเราเอง ยังไม่ได้เทียบ engine ภายนอก
> ส่วนการฝังลง ESP32 ยังไม่ได้ทำ
>
> **สูตรที่ได้ผลจนถึงตอนนี้ (จากการทดลอง):** ใช้ `wdl = 0.0` (net เลียนคะแนนของ engine ล้วนๆ)
> เทรน 200 superbatch และรอบถัดไปเทรนจากข้อมูล **ทุกรอบรวมกัน** ไม่ใช่เฉพาะรอบล่าสุด
> (`wdl 0.5` และ `0.3` แพ้ในการทดลองของเรา) ดู D-010 ใน [`decisions.md`](decisions.md)

## 1. ภาพรวมใน 30 วินาที

Wyrdmate เป็นโปรแกรมหมากรุกแบบคลาสสิก 3 ส่วนต่อกัน:

| ส่วน | ทำอะไร | เรียนรู้ได้ไหม |
|---|---|---|
| กฎหมากรุก | บอกว่าตาเดินไหนถูกกติกา (library `cozy-chess`) | ไม่ |
| การค้นหา | ลองเดินล่วงหน้าหลายตา (alpha-beta) | ไม่ |
| **การประเมิน (NNUE)** | ดูตำแหน่งแล้วให้คะแนนว่าใครได้เปรียบ | **ได้ ← ส่วนที่เราเทรน** |

การ "เทรน" จึงหมายถึงการทำให้ส่วนที่ 3 ฉลาดขึ้นเท่านั้น

วิธีที่ใช้คือ **supervised learning** (เรียนรู้แบบมีเฉลย) ด้วยเครื่องมือ
[bullet](https://github.com/jw1912/bullet) ไม่ใช่ reinforcement learning แบบ AlphaZero

## 2. NNUE คืออะไร

**NNUE** = Efficiently Updatable Neural Network คือ neural network เล็กๆ ที่ออกแบบให้
คำนวณใหม่ได้เร็วเมื่อหมากขยับแค่ 1-2 ตัว เหมาะกับหมากรุกและบอร์ดเล็กอย่าง ESP32

**โครงสร้างของเรา:** `(768 → 32) × 2 → 1`

```
กระดาน ──▶ 768 ตัวเลข (0/1) ──▶ ชั้นซ่อน 32 โหนด ──┐
(มุมมองฝ่ายที่ถึงตา)                                 ├─▶ รวมกัน ──▶ คะแนน 1 ตัว
กระดาน ──▶ 768 ตัวเลข (0/1) ──▶ ชั้นซ่อน 32 โหนด ──┘
(มุมมองอีกฝ่าย)
```

- **768** = หมาก 6 ชนิด × 2 สี × 64 ช่อง แต่ละตัวบอกว่า "ช่องนี้มีหมากชนิดนี้ไหม"
- **2 มุมมอง** = มองจากฝ่ายที่ถึงตา และจากอีกฝ่าย แล้วเอามารวมกัน
- **32** = จำนวนโหนดซ่อน (ปรับได้ ถ้าใหญ่ขึ้น แรงขึ้นแต่กิน RAM บน ESP32 มากขึ้น)
- **SCReLU** = ฟังก์ชันกระตุ้น (ยกกำลังสองหลังจำกัดค่า) เป็นตัวเลือกมาตรฐานของ bullet
- **Quantisation** = ปัดน้ำหนักเป็นจำนวนเต็ม int16 (QA=255, QB=64, scale=400)
  ไฟล์จึงเล็ก (~48 KB) และคำนวณบนไมโครคอนโทรลเลอร์ได้

ไฟล์ net คือ **ตารางตัวเลขน้ำหนัก** ไม่มีโค้ดข้างใน engine อ่านตารางแล้วบวกค่าของหมากที่อยู่บนกระดาน
ได้เป็นคะแนน

### ขั้นที่ 1 — Self-play สร้างข้อมูล (`datagen`)

ให้ engine เล่นหมากรุกกับตัวเองหลายพันเกม ระหว่างเล่นจดทุกตำแหน่งที่เข้าเกณฑ์ลงไฟล์

**รูปแบบหนึ่งบรรทัด**

```
rnb1kbnr/ppqppp2/6p1/1Bp4p/4P3/5P2/PPPP2PP/RNBQK1NR w KQkq h6 0 5 | 0 | 0.5
└──────────────────── FEN: สภาพกระดาน ────────────────────────┘   │    │
                                                                   │    └ ผลสุดท้ายของเกม
                                                                   │      1.0 ขาวชนะ / 0.5 เสมอ / 0.0 ดำชนะ
                                                                   └ คะแนนที่ engine ให้ (เซนติเบี้ย
                                                                     มุมมองฝ่ายขาว 100 = ได้เบี้ยหนึ่งตัว)
```

- **1 เกม = หลายบรรทัด** (ประมาณ 120 บรรทัด) ทุกบรรทัดของเกมเดียวกันมี "ผลสุดท้าย" เหมือนกัน
  เพราะเขียนย้อนหลังหลังเกมจบ
- `0.5` ท้ายบรรทัด **ไม่ได้แปลว่าตอนนั้นเสมอ** แต่แปลว่าเกมนี้ *จบ* ด้วยการเสมอ

**ขั้นตอนของแต่ละเกม**

1. **เดินสุ่ม 8-9 ตาแรก** เพื่อให้แต่ละเกมไม่ซ้ำกัน (engine เป็นอัลกอริทึมตายตัว ถ้าไม่สุ่ม
   ทุกเกมจะเหมือนกันหมด) ถ้าตำแหน่งที่ได้เสียเปรียบเกิน 3 เบี้ย จะทิ้งแล้วสุ่มใหม่
2. **engine เล่นต่อ** ด้วยการค้นหาที่จำกัด 5,000 nodes ต่อตา
3. **จดตำแหน่ง** เฉพาะที่ "สงบ": ไม่ถูกรุก, ตาที่เดินไม่ใช่การกิน/โปรโมต, คะแนนไม่ใช่รุกฆาต
4. **เกมจบเมื่อ:** รุกฆาต / เสมอตามกติกา / คะแนนเกิน ±1500 ติดกัน 4 ตา (ตัดสินให้ชนะ) /
   เดินครบ 300 ตา (นับเสมอ)
5. เริ่มเกมใหม่

**คำสั่ง**

```bash
wyrdmate-datagen [เกม] [nodes] [seed] [ไฟล์ออก] [net.bin (ไม่บังคับ)]
# ตัวอย่าง: 2,500 เกม, 5,000 nodes, seed 11
wyrdmate-datagen 2500 5000 11 data/part11.txt
```

ใส่ `net.bin` ท้ายคำสั่งเพื่อให้ engine ใช้ net นั้นประเมินตอนเล่น (สำหรับรอบที่ 2 เป็นต้นไป)
รันหลายโปรเซสขนานได้โดยใช้ seed ต่างกัน

**ผลรอบแรกของเรา:** 10,000 เกม ≈ 1.25 ล้านตำแหน่ง แบ่งเป็น ชนะ 120,018 / เสมอ 1,009,372 /
แพ้ 119,946 (เสมอ ~80% เพราะ eval ตอนนั้นนับแค่มูลค่าหมาก จึงไม่ค่อยรู้วิธีรุกฆาต
ผลเสมอส่วนใหญ่มาจากเหตุผลใด ยังไม่ได้นับแยก)

### ขั้นที่ 2 — แปลงและสับข้อมูล (`bullet-utils`)

bullet อ่านไฟล์ข้อความของเราตรงๆ ไม่ได้ ต้องแปลงเป็นรูปแบบไบนารีก่อน

```bash
cat data/part*.txt > data/all.txt
bullet-utils convert --from text --input data/all.txt --output data/all.data --threads 4
bullet-utils shuffle --input data/all.data --output data/train.data --mem-used-mb 1024
```

**ทำไมต้องสับ (shuffle):** ตำแหน่งที่ติดกันในเกมเดียวกันเกือบเหมือนกันหมด ถ้าป้อนตามลำดับ
net จะเห็นตำแหน่งคล้ายๆ กันติดกันเป็นก้อน แล้วเรียนรู้เอียง สับให้กระจายก่อนจึงสำคัญ

`bullet-utils` ไม่มีในโปรเจกต์ ต้อง build จาก repo ของ bullet (`crates/utils`)

### ขั้นที่ 3 — เทรนด้วย bullet (`trainer`)

bullet ทำซ้ำวงนี้กับทุกตำแหน่งหลายรอบ:

1. ให้ net **ทายคะแนน** ของตำแหน่ง
2. เทียบกับ **เฉลย** แล้วคำนวณ **loss** (ยิ่งทายห่างยิ่งสูง)
3. **ขยับน้ำหนัก** ทุกตัวนิดเดียวไปในทางที่ทำให้ loss ลดลง (optimiser ชื่อ AdamW)
4. ทำซ้ำเป็นล้านครั้ง

**เฉลยคืออะไร** เป็นการผสมสองอย่าง:

```
เฉลย = wdl × ผลเกม  +  (1 − wdl) × sigmoid(คะแนน engine / 400)
```

- `wdl` (ตั้งค่าตั้งต้น 0.5) คือน้ำหนักที่ให้ผลแพ้ชนะจริง
  - สูง → net เรียนรู้ผลลัพธ์จริง แต่ผลเกมมีสัญญาณรบกวนเยอะ (โดยเฉพาะเมื่อเสมอเกือบหมด)
  - ต่ำ → net เลียนแบบคะแนนของ engine เป็นหลัก เสถียรกว่า แต่เก่งได้ไม่เกินครูของมัน
- `sigmoid` แปลงคะแนนเซนติเบี้ยเป็นช่วง 0-1 ให้อยู่สเกลเดียวกับผลเกม

**ศัพท์ที่จะเจอใน log**

| คำ | ความหมาย |
|---|---|
| batch | ข้อมูลก้อนหนึ่ง (16,384 ตำแหน่ง) ที่ปรับน้ำหนักหนึ่งครั้ง |
| superbatch | ชุดของ batch หลายก้อน แล้วบันทึก checkpoint หนึ่งครั้ง |
| loss | ค่าที่ทายผิดจากเฉลย ยิ่งน้อยยิ่งดี |
| learning rate | ขนาดก้าวที่ขยับน้ำหนักในแต่ละครั้ง (เราลดเป็นขั้นช่วงท้าย) |

**คำสั่ง**

```bash
wyrdmate-trainer <data.data> [superbatches=20] [batches_per_sb=1000] [batch_size=16384] [wdl=0.5] [net_id=wyrd]
# รอบแรกที่ใช้จริง (76 batch ≈ ข้อมูล 1 รอบพอดี)
wyrdmate-trainer data/train.data 20 76 16384
```

ต้อง build ด้วย `--features cuda` เพื่อเทรนบน GPU และบน Windows ต้องมีโฟลเดอร์
`...\CUDA\v13.3\bin\x64` อยู่ใน `PATH` (ไม่งั้นรันแล้วหา `cublas64_13.dll` ไม่เจอ)

**ผลลัพธ์** อยู่ใน `checkpoints/<net_id>-<superbatch>/` (ไม่เข้า git):

| ไฟล์ | คืออะไร |
|---|---|
| `quantised.bin` | **net ที่ใช้งานจริง** (~48 KB) |
| `raw.bin` | น้ำหนักทศนิยมเต็มรูปแบบ ใช้เทรนต่อ |
| `optimiser_state/` | ความจำของตัวเทรน ใช้เมื่อเทรนต่อ |
| `log.txt` | บันทึก loss |

**CUDA ช่วยตรงไหน** ใช้เฉพาะขั้นนี้ ให้การ์ดจอคำนวณแทนซีพียู (เทรนข้อมูล 1.25 ล้านตำแหน่ง
เสร็จในไม่กี่วินาทีบน RTX 4060) ขั้นอื่นและ ESP32 ไม่ใช้ CUDA

### ขั้นที่ 4 — ใส่ net เข้า engine แล้วแข่งทดสอบ

engine โหลด net ผ่านคำสั่ง UCI:

```text
setoption name EvalFile value checkpoints/wyrd-20/quantised.bin
setoption name Nodes value 20000
```

จากนั้นเอา engine ที่ใช้ net ไปแข่งกับ engine เดิม **หลายร้อยเกม** ด้วยโปรแกรมแข่ง
(`fastchess` / `cutechess-cli`) แล้วดูผล Elo

> **กฎของโปรเจกต์:** net ใหม่จะถูกรับก็ต่อเมื่อชนะ **เกินช่วงความคลาดเคลื่อน**
> ค่า loss ต่ำอย่างเดียวพิสูจน์อะไรไม่ได้ (net อาจแค่จำข้อมูลได้ หรือข้อมูลเองง่ายเกินไป)

### ขั้นที่ 5 — วนซ้ำ

ถ้า net ผ่านการแข่ง ให้ใช้ engine ที่ใช้ net นั้นสร้างข้อมูลรอบใหม่ (ใส่ `net.bin` ท้ายคำสั่ง datagen)
คะแนนในข้อมูลจะแม่นขึ้น เทรนอีกรอบ แล้วแข่งอีกครั้ง วนไปจนความแรงไม่เพิ่มหรือถึงระดับที่ต้องการ

**จะตันไหม:** ตันแน่นอนในที่สุด สาเหตุหลักมี 3 อย่าง
1. net เล็กเกินจนเรียนรู้เพิ่มไม่ได้ (เพดานตามขนาด net ซึ่งถูกจำกัดด้วย RAM ของ ESP32)
2. ข้อมูลจาก engine ตัวเองไม่มีอะไรใหม่ให้เรียน
3. เทรนซ้ำชุดเดิมจน net "จำ" แทนที่จะเข้าใจ

สำหรับเป้าหมาย "ไม่แรงแต่ฉลาด" การตันไม่ใช่ปัญหา แค่หยุดเมื่อถึงระดับที่ต้องการ
แล้วคุมความแรงด้วยจำนวน nodes ตอนเล่น

### ขั้นที่ 6 — ฝังลง ESP32 (ยังไม่ได้ทำ)

แยกส่วนอ่าน net และคำนวณออกเป็นโค้ด `no_std` ใช้ int16/int8 ทดสอบบนเครื่องก่อนว่าผลตรงกับ
เวอร์ชันบน PC ทุกตำแหน่ง แล้วค่อยลงบอร์ด ฝัง net ด้วย `include_bytes!`

## 4. คำถามที่พบบ่อย

**bullet เล่นหมากรุกเองไหม?** ไม่ มันแค่อ่านไฟล์ข้อมูลแล้วปรับน้ำหนัก คนที่เล่นคือ engine ของเรา

**net รู้กฎหมากรุกไหม?** ไม่เลย กฎอยู่ใน `cozy-chess` net รู้แค่ว่า "หน้าตาแบบนี้มักดีหรือไม่ดี"

**net เลือกตาเดินให้ไหม?** ไม่โดยตรง net แค่ให้คะแนนตำแหน่ง การค้นหา alpha-beta
ลองเดินหลายทางแล้วเลือกทางที่ net ให้คะแนนปลายทางดีที่สุด

**ทำไมต้องสุ่มเปิดเกม?** เพื่อไม่ให้ทุกเกมซ้ำกัน แต่ตำแหน่งจากการสุ่มอาจไม่เหมือนเกมจริง
ผลกระทบต่อความแรงยังไม่ได้ทดสอบ (ทดลองเทียบกับ opening book ได้ เพราะเทรนใช้เวลาไม่กี่วินาที)

**ทำไมเสมอ ~80%?** น่าจะเพราะ engine รอบแรกประเมินแค่มูลค่าหมาก จึงรุกฆาตไม่เก่ง และเกมที่เดินครบ
300 ตาถูกนับเสมอ (ยังไม่ได้วัดสัดส่วนแต่ละเหตุผล) ข้อมูลรอบถัดไปควรดีขึ้นเมื่อ engine ใช้ net

**ต้องเทรนซ้ำกี่รอบ?** ไม่มีตัวเลขตายตัว ดูจากผลแข่ง A/B ของแต่ละรอบ

## 5. ข้อมูลที่ต้องบันทึกทุกครั้งที่ได้ net ใหม่

เพื่อให้สร้างซ้ำได้ (กฎข้อ 1 ใน `CLAUDE.md`) เก็บไว้ข้างไฟล์ net ใน `nets/`:

- git commit hash ของโค้ดตอนเทรน และ rev ของ bullet
