## 1. ภาพรวม

Wyrdmate มี 3 ส่วน (กฎหมากรุก, search, evaluation) **training หมายถึงการปรับปรุง evaluation (net) เท่านั้น** ([ARCHITECTURE.md](ARCHITECTURE.md) ข้อ 2)

วิธีที่ใช้คือ **supervised learning** (เรียนรู้จากเฉลย) ด้วย [bullet](https://github.com/jw1912/bullet) ไม่ใช่ reinforcement learning แบบ AlphaZero (D-002)
เฉลยมาจาก self-play ของ engine เอง **ไม่ใช้ Stockfish เป็นครู** (Stockfish ใช้วัดความแรงเท่านั้น)

## 2. ขั้นตอน

```text
 [1] self-play        [2] แปลง/สับ        [3] training        [4] ใส่ net ใน engine
 สร้างข้อมูล   ──▶    ข้อมูล        ──▶   bullet       ──▶    + A/B match
 (datagen)            (bullet-utils)      (trainer)            │
   ▲                                                           │ ชนะชัดเจน (ขอบล่าง Elo > 0)
   └────────────── [5] ใช้ net ใหม่สร้างข้อมูลรอบถัดไป ◀────────┘
                                                               │
                                                      [6] ฝังลง ESP32 (ยังไม่ได้ทำ)
```

### ขั้นที่ 1: self-play สร้างข้อมูล (`datagen`)

ให้ engine เล่นกับตัวเองหลายพันเกม บันทึกทุกตำแหน่งที่เข้าเกณฑ์ลงไฟล์ รูปแบบหนึ่งบรรทัด:

```text
rnb1kbnr/ppqppp2/6p1/1Bp4p/4P3/5P2/PPPP2PP/RNBQK1NR w KQkq h6 0 5 | 0 | 0.5
└──────────────────── FEN: สภาพกระดาน ──────────────────────────┘   │    └ ผลสุดท้ายของเกม: 1.0 ขาวชนะ / 0.5 เสมอ / 0.0 ดำชนะ
                                                                    └ คะแนนที่ engine ให้ (cp มุมมองฝ่ายขาว)
```

- 1 เกม ≈ 120 บรรทัด ทุกบรรทัดของเกมเดียวกันมี "ผลสุดท้าย" เหมือนกัน (เขียนย้อนหลังหลังเกมจบ) ค่า `0.5` ไม่ได้แปลว่าตำแหน่งนั้นเสมอ แต่เกมนั้น *จบ* ด้วยการเสมอ
- **ต่อหนึ่งเกม:** เดินสุ่ม 8–9 ตาแรกเพื่อให้เกมต่างกัน (ทิ้งและสุ่มใหม่ถ้าเสียเปรียบเกิน 3 เบี้ย) → engine เล่นต่อด้วย node limit ที่กำหนด (ปกติ 5,000)
  → บันทึกเฉพาะตำแหน่ง **quiet** (ไม่ถูกรุก, move ที่เดินไม่ใช่ capture/promotion, คะแนนไม่ใช่รุกฆาต)
  → จบเมื่อรุกฆาต / เสมอตามกติกา / คะแนนเกิน ±1,500 ติดกัน 4 ตา (ตัดสินให้ชนะ) / ครบ 300 ตา (นับเสมอ)

```bash
wyrdmate-datagen [เกม] [nodes] [seed] [ไฟล์ออก] [net.bin (ไม่บังคับ)]
wyrdmate-datagen 2500 5000 81 data/r7part81.txt nets/wyrd-vi.bin   # ตัวอย่างรอบ 7 (r7a)
```

ระบุ `net.bin` เพื่อให้ engine ใช้ net นั้นประเมินระหว่างเล่น (ตั้งแต่รอบ 2) รันได้หลายโปรเซสพร้อมกันโดยใช้ seed ต่างกัน
(รอบละ 4 งาน × 2,500 เกม ใช้เวลาราว 10 นาทีบนเครื่องพัฒนา)

### ขั้นที่ 2: แปลงและสับข้อมูล (`bullet-utils`)

bullet อ่านไฟล์ข้อความของ datagen ตรง ๆ ไม่ได้ ต้องแปลงเป็นไบนารีก่อน แล้ว **สับ (shuffle)** เพราะตำแหน่งติดกันในเกมเดียวกันคล้ายกันมาก
ถ้าป้อนตามลำดับ net จะเรียนแบบเอนเอียง

```bash
cat data/r6all.txt data/r7part*.txt > data/r7all.txt        # ข้อมูลทุกรอบรวมกัน
bullet-utils convert --from text --input data/r7all.txt --output data/r7all.data --threads 4
bullet-utils shuffle --input data/r7all.data --output data/r7train.data --mem-used-mb 1024
```

`bullet-utils` ไม่ได้อยู่ในโครงการ ต้อง build จาก repository ของ bullet (`crates/utils`)

### ขั้นที่ 3: training ด้วย bullet (`trainer`)

```bash
wyrdmate-trainer <data.data> [superbatches=20] [batches_per_sb=1000] [batch_size=16384] [wdl=0.5] [net_id=wyrd] [hidden=32]
wyrdmate-trainer data/r7train.data 200 402 16384 0.0 r7a      # สูตรปัจจุบัน
```

- ตั้ง `batches_per_sb × batch_size` ให้ใกล้เคียงจำนวนตำแหน่งในชุดข้อมูล (หนึ่ง superbatch ≈ ข้อมูลหนึ่งรอบ) เช่น 6,579,953 ตำแหน่ง ÷ 16,384 ≈ 402
- บน GPU ต้อง build ด้วย `--features cuda` และบน Windows เพิ่ม `%CUDA_PATH%\bin\x64` ใน `PATH` (ไม่งั้นไม่พบ `cublas64_13.dll`) และรันจาก PowerShell
  ใช้เวลาราว 36 วินาทีต่อ 200 superbatches บน RTX 4060 (ข้อมูล ~6.6 ล้านตำแหน่ง)

ผลลัพธ์อยู่ใน `checkpoints/<net_id>-<superbatch>/` (ไม่เข้า git):

| ไฟล์ | คืออะไร |
|---|---|
| `quantised.bin` | **net ที่ใช้งานจริง** (~48 KB) |
| `raw.bin` | weights ทศนิยมเต็มรูปแบบ ใช้เทรนต่อ |
| `optimiser_state/` | สถานะของ optimiser ใช้เมื่อเทรนต่อ |
| `log.txt` | บันทึก loss (`superbatch,batch,loss`) เขียนตอนบันทึก checkpoint |

### ขั้นที่ 4: ใส่ net ใน engine แล้วแข่ง

```text
setoption name EvalFile value checkpoints/r7a-200/quantised.bin
setoption name Nodes value 10000
```

แล้วรัน A/B match กับ net เดิมด้วย `scripts/ab.ps1` ([EVALUATION.md](EVALUATION.md) ข้อ 3)

> **กฎของโครงการ:** net ใหม่ถูกรับก็ต่อเมื่อชนะ **เกิน error bar** loss ที่ต่ำลงอย่างเดียวไม่เป็นหลักฐาน

### ขั้นที่ 5: วนซ้ำ

ถ้า net ผ่าน ใช้ engine ที่ใช้ net นั้นสร้างข้อมูลรอบใหม่ (ระบุ `net.bin` ท้ายคำสั่ง datagen) แล้วเทรนและแข่งอีกครั้ง

### ขั้นที่ 6: ฝังลง ESP32 (ยังไม่ได้ทำ)

แยกส่วนอ่าน net และคำนวณเป็นโค้ด `no_std` ที่ใช้ `i16` ทดสอบบนพีซีก่อนว่าผลตรงกับ engine ทุกตำแหน่ง แล้วฝัง net ด้วย `include_bytes!` ดู [ROADMAP.md](ROADMAP.md)

## 3. Training คืออะไร

bullet ทำกระบวนการต่อไปนี้ซ้ำกับทุกตำแหน่งหลายรอบ:

1. ให้ net **ทำนายคะแนน** ของตำแหน่ง
2. เทียบกับ **เฉลย** แล้วคำนวณ **loss** (ยิ่งคลาดเคลื่อนมาก ยิ่งสูง)
3. **ปรับ weights** ทีละเล็กน้อยในทิศทางที่ทำให้ loss ลดลง (optimiser ที่ใช้คือ AdamW)
4. ทำซ้ำเป็นล้านครั้ง

**เฉลย** เป็นการผสมสองอย่าง:

```text
เฉลย = wdl × ผลเกม  +  (1 − wdl) × sigmoid(คะแนน engine / 400)
```

- `wdl` คือ weight ที่ให้ผลแพ้/เสมอ/ชนะจริง (ค่าตั้งต้นของ trainer 0.5 แต่ **ใช้ 0.1 ตั้งแต่รอบ 8** ตาม D-012 ก่อนหน้านั้นใช้ 0.0 ตาม D-010)
  - ค่าสูง: net เรียนจากผลจริง แต่ผลเกมมี noise มาก โดยเฉพาะเมื่อเสมอเป็นส่วนใหญ่
  - ค่าต่ำ: net เรียนแบบคะแนนของ engine เป็นหลัก เสถียรกว่า แต่เก่งไม่เกิน engine ที่เป็นผู้สอนมากนัก
- `sigmoid` แปลง cp เป็นช่วง 0–1 ให้อยู่สเกลเดียวกับผลเกม

| คำที่เจอใน log | ความหมาย |
|---|---|
| **batch** | ข้อมูลก้อนหนึ่ง (16,384 ตำแหน่ง) ที่ใช้ปรับ weights หนึ่งครั้ง |
| **superbatch** | ชุดของ batch หลายก้อน ครบแล้วบันทึก checkpoint หนึ่งครั้ง |
| **loss** | ความคลาดเคลื่อนจากเฉลย ยิ่งน้อยยิ่งทายใกล้ **เปรียบเทียบข้ามชุดข้อมูลไม่ได้** |
| **learning rate** | ขนาดก้าวของการปรับ weights (ลดเป็นขั้นช่วงท้าย) |

## 4. สูตรที่ใช้ (D-010, แก้ `wdl` โดย D-012)

จากการทดลองของโครงการ (แมตช์ 600 เกมเทียบรุ่นก่อน):

- **`wdl = 0.1`** (D-012 ตั้งแต่รอบ 8): ผสมผลเกมจริง 10% กับคะแนนของ engine 90% ทดสอบบนข้อมูลรอบ 8 ชุดเดียวกัน: 0.0 ได้ −9 / −12 Elo, **0.1 ได้ +57 / +80**, 0.2 ได้ +20 / +38, 0.3 ได้ −60 / −22, 0.4 ได้ −114 / −113 (ที่ 10k / 50k node เทียบ wyrd-vii; EVALUATION.md ข้อ 8.3) ผสมน้อยช่วย ผสมมากพัง
- ก่อนรอบ 8 ใช้ `wdl = 0.0` (D-010): ตอนนั้น wdl 0.5 ได้ −148 ± 24 Elo และ 0.3 ได้ −35 ± 19 เทียบ material eval ขณะที่ 0.0 ได้ +115 ± 23 (ข้อมูลรอบแรกเสมอ ~80%)
- เทรน 200 superbatches
- ตั้งแต่รอบ 3 เทรนจาก **ข้อมูลทุกรอบรวมกัน** (ข้อมูลรอบ 3 อย่างเดียวได้ +63 เทียบ wyrd-ii ส่วนรอบ 2+3 รวมกันได้ +81)

คำอธิบาย (ผลเกมมี noise เมื่อเสมอเป็นส่วนใหญ่ ข้อมูลที่หลากหลายกว่าช่วยได้) เป็น **สมมติฐาน ยังไม่ได้ทดสอบแยก** ควรทบทวนถ้าข้อมูลไม่ได้เสมอเป็นส่วนใหญ่อีกต่อไป
(รอบแรกเสมอราว 80%)

## 6. ขีดจำกัดของวงวน

กำไรต่อรอบ: +115, +81, +31, +64, +47 แล้วรอบ 7 ไม่ผ่านเกณฑ์ แนวโน้มคือลดลง สาเหตุที่เป็นไปได้ (ยังไม่ได้แยก):

1. **net เล็กเกินไป** (hidden size 32) ทดสอบแล้วว่าไม่น่าใช่: net ใหญ่ขึ้นเพิ่ม Elo ที่ node เท่ากันได้ไม่มาก และไม่คุ้มที่เวลาเท่ากัน ([EVALUATION.md](EVALUATION.md) ข้อ 8.1)
2. **ข้อมูลที่ engine สร้างเองไม่มีสิ่งใหม่ให้เรียน** (คุณภาพ label ถูกจำกัดด้วย node limit ของ datagen)
3. **เทรนซ้ำกับชุดข้อมูลเดิม** จน net จดจำแทนที่จะสรุปรูปแบบ

ทางที่ไม่ต้องใช้ RAM เพิ่ม: ปรับ search ต่อ, datagen ที่ node สูงขึ้น, ข้อมูลมากขึ้นต่อรอบ, หรือสอน net เล็กจาก net ใหญ่ (distillation) ดู [ROADMAP.md](ROADMAP.md)
สำหรับเป้าหมาย "weak but clever" การถึงขีดจำกัดไม่ใช่ปัญหา เพียงหยุดเมื่อถึงระดับที่ต้องการ แล้วควบคุมความแรงด้วย node limit ขณะเล่น

## 7. คำถามที่พบบ่อย

**bullet เล่นหมากรุกเองหรือไม่?** ไม่ bullet เพียงอ่านข้อมูลและปรับ weights ผู้เล่นคือ engine ของโครงการ

**net รู้กฎหมากรุกหรือไม่?** ไม่ กฎอยู่ใน `cozy-chess` net รู้เพียงว่าตำแหน่งลักษณะใดมักดีหรือไม่ดี

**net เลือก move ให้โดยตรงหรือไม่?** ไม่ net ให้คะแนนตำแหน่งเท่านั้น search ลองหลายทางแล้วเลือกทางที่ net ให้คะแนนตำแหน่งปลายทางดีที่สุด ([NET.md](NET.md) ข้อ 1)

**เหตุใดจึงสุ่มเปิดเกม?** เพื่อให้แต่ละเกมต่างกัน (engine เล่นแบบ deterministic ถ้าไม่สุ่มทุกเกมเหมือนกัน) แต่ตำแหน่งจากการสุ่มอาจไม่เหมือนเกมจริง
ผลกระทบต่อความแรงยังไม่ได้ทดสอบ (ทดลองเทียบกับ opening book ได้ เพราะการเทรนใช้เวลาสั้น)

**เหตุใดผลเสมอรอบแรกจึงสูงราว 80%?** สันนิษฐานว่า engine รอบแรกใช้ material eval จึงรุกฆาตได้ไม่ดี และเกมที่ครบ 300 ตานับเป็นเสมอ ยังไม่ได้แยกสัดส่วนของแต่ละสาเหตุ

**ควรเทรนกี่รอบ?** ไม่มีตัวเลขตายตัว ดูจากผล A/B ของแต่ละรอบ (ข้อ 6)

## 8. ข้อมูลที่ต้องบันทึกทุกครั้งที่ได้ net ใหม่

เพื่อให้สร้างซ้ำได้ (กฎเหล็กข้อ 1 ใน `CLAUDE.md`) ต้องบันทึกใน `nets/RECORDS.md`:

- git commit hash ของโค้ดตอนเทรน และ rev ของ bullet
- ค่าที่ใช้กับ trainer (superbatches, batches_per_sb, batch_size, wdl, net_id)
- ข้อมูลที่ใช้ (seed, nodes, จำนวนเกม, net และรุ่น search ที่ใช้สร้างข้อมูล, จำนวนตำแหน่ง)
- ผลแข่งเทียบกับรุ่นก่อนหน้า (จำนวนเกม, Elo ± error bar)
