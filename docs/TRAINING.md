# การเทรน NNUE ของ Wyrdmate

เอกสารนี้อธิบายกระบวนการสร้างฟังก์ชันประเมินตำแหน่ง (NNUE) ของ Wyrdmate ตั้งแต่ข้อมูลดิบจนถึงไฟล์ net
ผู้อ่านไม่จำเป็นต้องมีพื้นฐานด้านปัญญาประดิษฐ์มาก่อน

**สารบัญ:** [1. ภาพรวม](#1-ภาพรวม) · [2. NNUE](#2-nnue-คืออะไร) · [3. ขั้นตอน](#3-ขั้นตอนทั้งหมด) ·
[4. คำถามที่พบบ่อย](#4-คำถามที่พบบ่อย) · [5. ข้อมูลที่ต้องบันทึก](#5-ข้อมูลที่ต้องบันทึกทุกครั้งที่ได้-net-ใหม่)

> **สถานะล่าสุด:** วงวนดำเนินการครบ 4 รอบ net ที่ผ่านการแข่งอยู่ใน `nets/` (`wyrd-i` ถึง `wyrd-iv`)
> net ปัจจุบัน `wyrd-iv` ชนะ `wyrd-iii` **+31 ± 22 Elo** และชนะ engine นับมูลค่าหมาก **+212 ± 27 Elo**
> (600 เกมต่อคู่) ผลที่เพิ่มต่อรอบลดลงตามลำดับ (+115, +81, +31)
> รายละเอียดอยู่ใน [`nets/RECORDS.md`](../nets/RECORDS.md) ผลทั้งหมดเทียบกับ engine รุ่นก่อนของโครงการเอง
> ยังไม่ได้เทียบกับ engine ภายนอก และการฝังลง ESP32 ยังไม่ได้ดำเนินการ
>
> **สูตรที่ได้ผลจากการทดลอง (D-010):** ใช้ `wdl = 0.0` (net เรียนแบบคะแนนของ engine ทั้งหมด)
> เทรน 200 superbatch และตั้งแต่รอบที่ 3 ให้เทรนจากข้อมูล **ทุกรอบรวมกัน**
> ส่วน `wdl` 0.5 และ 0.3 ให้ผลแพ้ในการทดลองของโครงการ

## 1. ภาพรวม

Wyrdmate เป็นโปรแกรมหมากรุกแบบคลาสสิก 3 ส่วนต่อกัน:

| ส่วน | ทำอะไร | เรียนรู้ได้ไหม |
|---|---|---|
| กฎหมากรุก | บอกว่าตาเดินไหนถูกกติกา (library `cozy-chess`) | ไม่ |
| การค้นหา | ลองเดินล่วงหน้าหลายตา (alpha-beta) | ไม่ |
| **การประเมิน (NNUE)** | ดูตำแหน่งแล้วให้คะแนนว่าใครได้เปรียบ | **ได้ ← ส่วนที่เราเทรน** |

ดังนั้น "การเทรน" ในเอกสารนี้หมายถึงการปรับปรุงส่วนที่ 3 เท่านั้น

วิธีที่ใช้คือ **supervised learning** (การเรียนรู้แบบมีเฉลย) ด้วยเครื่องมือ
[bullet](https://github.com/jw1912/bullet) ไม่ใช่ reinforcement learning แบบ AlphaZero (D-002)

## 2. NNUE คืออะไร

**NNUE** (Efficiently Updatable Neural Network) คือ neural network ขนาดเล็กที่ออกแบบให้
คำนวณใหม่ได้รวดเร็วเมื่อหมากเปลี่ยนตำแหน่งเพียง 1–2 ตัว จึงเหมาะกับหมากรุกและบอร์ดขนาดเล็กอย่าง ESP32

**โครงสร้างที่ใช้:** `(768 → 32) × 2 → 1` (รายละเอียดทางเทคนิคและรูปแบบไฟล์ดู [ARCHITECTURE.md](ARCHITECTURE.md))

```
กระดาน ──▶ 768 ตัวเลข (0/1) ──▶ ชั้นซ่อน 32 โหนด ──┐
(มุมมองฝ่ายที่ถึงตา)                                 ├─▶ รวมกัน ──▶ คะแนน 1 ตัว
กระดาน ──▶ 768 ตัวเลข (0/1) ──▶ ชั้นซ่อน 32 โหนด ──┘
(มุมมองอีกฝ่าย)
```

- **768** = หมาก 6 ชนิด × 2 สี × 64 ช่อง แต่ละตัวบอกว่า "ช่องนี้มีหมากชนิดนี้ไหม"
- **2 มุมมอง** = มองจากฝ่ายที่ถึงตา และจากอีกฝ่าย แล้วเอามารวมกัน
- **32** = จำนวนโหนดซ่อน (ปรับได้ ถ้าใหญ่ขึ้น แรงขึ้นแต่กิน RAM บน ESP32 มากขึ้น)
- **SCReLU** = ฟังก์ชันกระตุ้น (ยกกำลังสองหลังจำกัดค่า) เป็นตัวเลือกมาตรฐานของ bullet
- **Quantisation** = ปัดน้ำหนักเป็นจำนวนเต็ม int16 (QA=255, QB=64, scale=400)
  ไฟล์จึงเล็ก (~48 KB) และคำนวณบนไมโครคอนโทรลเลอร์ได้

ไฟล์ net คือ **ตารางตัวเลขน้ำหนัก** ไม่มีโค้ดอยู่ภายใน engine อ่านตารางนี้แล้วรวมค่าของหมากที่อยู่บนกระดาน
เพื่อให้ได้คะแนน

## 3. ขั้นตอนทั้งหมด

```
   ┌──────────────────────────────────────────────────────────┐
   │                                                          │
   ▼                                                          │
 [1] Self-play        [2] แปลง/สับ       [3] เทรน        [4] ใส่ net ใน engine
 สร้างข้อมูล    ──▶   ข้อมูล       ──▶   bullet    ──▶   + แข่งทดสอบ A/B
 (datagen)            (bullet-utils)     (trainer)         │
                                                           │ ชนะชัดเจน
                                                           ▼
                                                  [5] วนกลับไปข้อ 1
                                                  (ใช้ engine ใหม่สร้างข้อมูล)
                                                           │
                                                           ▼
                                                  [6] ฝังลง ESP32 (ยังไม่ได้ทำ)
```

### ขั้นที่ 1 — Self-play สร้างข้อมูล (`datagen`)

ให้ engine เล่นหมากรุกกับตัวเองหลายพันเกม และบันทึกทุกตำแหน่งที่เข้าเกณฑ์ลงไฟล์

**รูปแบบหนึ่งบรรทัด**

```
rnb1kbnr/ppqppp2/6p1/1Bp4p/4P3/5P2/PPPP2PP/RNBQK1NR w KQkq h6 0 5 | 0 | 0.5
└──────────────────── FEN: สภาพกระดาน ────────────────────────┘   │    │
                                                                   │    └ ผลสุดท้ายของเกม
                                                                   │      1.0 ขาวชนะ / 0.5 เสมอ / 0.0 ดำชนะ
                                                                   └ คะแนนที่ engine ให้ (เซนติเบี้ย
                                                                     มุมมองฝ่ายขาว 100 = ได้เบี้ยหนึ่งตัว)
```

- **1 เกม = หลายบรรทัด** (ประมาณ 120 บรรทัด) ทุกบรรทัดของเกมเดียวกันมี "ผลสุดท้าย" เหมือนกัน
  เพราะเขียนย้อนหลังหลังเกมจบ
- ค่า `0.5` ท้ายบรรทัด **ไม่ได้หมายความว่าตำแหน่งนั้นเสมอ** แต่หมายความว่าเกมดังกล่าว *จบ* ด้วยการเสมอ

**ขั้นตอนของแต่ละเกม**

1. **เดินสุ่ม 8–9 ตาแรก** เพื่อให้แต่ละเกมแตกต่างกัน (engine ทำงานแบบกำหนดแน่นอน หากไม่สุ่ม
   ทุกเกมจะเหมือนกัน) หากตำแหน่งที่ได้เสียเปรียบเกิน 3 เบี้ย จะทิ้งและสุ่มใหม่
2. **engine เล่นต่อ** ด้วยการค้นหาที่จำกัด 5,000 nodes ต่อตา
3. **จดตำแหน่ง** เฉพาะที่ "สงบ": ไม่ถูกรุก, ตาที่เดินไม่ใช่การกิน/โปรโมต, คะแนนไม่ใช่รุกฆาต
4. **เกมจบเมื่อ:** รุกฆาต / เสมอตามกติกา / คะแนนเกิน ±1500 ติดกัน 4 ตา (ตัดสินให้ชนะ) /
   เดินครบ 300 ตา (นับเสมอ)
5. เริ่มเกมใหม่

**คำสั่ง**

```bash
wyrdmate-datagen [เกม] [nodes] [seed] [ไฟล์ออก] [net.bin (ไม่บังคับ)]
# ตัวอย่าง: 2,500 เกม, 5,000 nodes, seed 11
wyrdmate-datagen 2500 5000 11 data/part11.txt
```

ระบุ `net.bin` ท้ายคำสั่งเพื่อให้ engine ใช้ net นั้นประเมินระหว่างเล่น (ใช้ตั้งแต่รอบที่ 2)
สามารถรันหลายโปรเซสพร้อมกันได้โดยกำหนด seed ต่างกัน

**ผลของรอบแรก:** 10,000 เกม ได้ประมาณ 1.25 ล้านตำแหน่ง แบ่งเป็น ชนะ 120,018 / เสมอ 1,009,372 /
แพ้ 119,946 (เสมอประมาณ 80% สันนิษฐานว่าเพราะ eval ในขณะนั้นนับเพียงมูลค่าหมาก จึงรุกฆาตได้ไม่ดี
ทั้งนี้ยังไม่ได้แยกนับสาเหตุของผลเสมอ)

### ขั้นที่ 2 — แปลงและสับข้อมูล (`bullet-utils`)

bullet ไม่สามารถอ่านไฟล์ข้อความของ datagen ได้โดยตรง จึงต้องแปลงเป็นรูปแบบไบนารีก่อน

```bash
cat data/part*.txt > data/all.txt
bullet-utils convert --from text --input data/all.txt --output data/all.data --threads 4
bullet-utils shuffle --input data/all.data --output data/train.data --mem-used-mb 1024
```

**เหตุผลที่ต้องสับ (shuffle):** ตำแหน่งที่อยู่ติดกันในเกมเดียวกันมีความคล้ายกันมาก
หากป้อนตามลำดับ net จะเห็นตำแหน่งคล้ายกันเป็นกลุ่มต่อเนื่องและเรียนรู้อย่างเอนเอียง
การสับให้กระจายก่อนจึงจำเป็น

`bullet-utils` ไม่ได้อยู่ในโครงการ ต้อง build จาก repository ของ bullet (`crates/utils`)

### ขั้นที่ 3 — เทรนด้วย bullet (`trainer`)

bullet ทำกระบวนการต่อไปนี้ซ้ำกับทุกตำแหน่งหลายรอบ:

1. ให้ net **ทำนายคะแนน** ของตำแหน่ง
2. เทียบกับ **เฉลย** และคำนวณ **loss** (ยิ่งคลาดเคลื่อนมาก ค่ายิ่งสูง)
3. **ปรับน้ำหนัก** ทีละเล็กน้อยในทิศทางที่ทำให้ loss ลดลง (ตัวปรับค่าคือ AdamW)
4. ทำซ้ำเป็นล้านครั้ง

**เฉลยคืออะไร** เป็นการผสมสองอย่าง:

```
เฉลย = wdl × ผลเกม  +  (1 − wdl) × sigmoid(คะแนน engine / 400)
```

- `wdl` คือน้ำหนักที่ให้กับผลแพ้/เสมอ/ชนะจริง (ค่าตั้งต้นของ trainer คือ 0.5 แต่ **แนะนำให้ระบุ 0.0** ตาม D-010)
  - ค่าสูง → net เรียนจากผลลัพธ์จริง แต่ผลเกมมีสัญญาณรบกวนมาก (โดยเฉพาะเมื่อเสมอเป็นส่วนใหญ่)
  - ค่าต่ำ → net เรียนแบบคะแนนของ engine เป็นหลัก เสถียรกว่า แต่มีขอบเขตความสามารถไม่เกิน engine ที่เป็นผู้สอน
- `sigmoid` แปลงคะแนนเซนติเบี้ยเป็นช่วง 0-1 ให้อยู่สเกลเดียวกับผลเกม

**ศัพท์ที่จะเจอใน log**

| คำ | ความหมาย |
|---|---|
| batch | ข้อมูลก้อนหนึ่ง (16,384 ตำแหน่ง) ที่ใช้ปรับน้ำหนักหนึ่งครั้ง |
| superbatch | ชุดของ batch หลายก้อน เมื่อครบจะบันทึก checkpoint หนึ่งครั้ง |
| loss | ความคลาดเคลื่อนจากเฉลย ยิ่งน้อยยิ่งดี (เปรียบเทียบข้ามชุดข้อมูลไม่ได้) |
| learning rate | ขนาดก้าวของการปรับน้ำหนัก (ลดเป็นขั้นในช่วงท้าย) |

**คำสั่ง**

```bash
wyrdmate-trainer <data.data> [superbatches=20] [batches_per_sb=1000] [batch_size=16384] [wdl=0.5] [net_id=wyrd]

# ตัวอย่างสูตรปัจจุบัน (รอบที่ 4: 212 batch ≈ ข้อมูลหนึ่งรอบ)
wyrdmate-trainer data/r234train.data 200 212 16384 0.0 r234a
```

ค่า `batches_per_sb` ควรให้ผลคูณกับ `batch_size` ใกล้เคียงจำนวนตำแหน่งในชุดข้อมูล
(หนึ่ง superbatch ≈ ข้อมูลหนึ่งรอบ) ดูตัวอย่างค่าจริงของแต่ละ net ใน [`nets/RECORDS.md`](../nets/RECORDS.md)

การเทรนบน GPU ต้อง build ด้วย `--features cuda` และบน Windows ต้องเพิ่มโฟลเดอร์
`...\CUDA\v13.3\bin\x64` ใน `PATH` (มิฉะนั้นจะไม่พบ `cublas64_13.dll`)

**ผลลัพธ์** อยู่ใน `checkpoints/<net_id>-<superbatch>/` (ไม่เข้า git):

| ไฟล์ | คืออะไร |
|---|---|
| `quantised.bin` | **net ที่ใช้งานจริง** (~48 KB) |
| `raw.bin` | น้ำหนักทศนิยมเต็มรูปแบบ ใช้เทรนต่อ |
| `optimiser_state/` | ความจำของตัวเทรน ใช้เมื่อเทรนต่อ |
| `log.txt` | บันทึก loss |

**บทบาทของ CUDA:** ใช้เฉพาะขั้นตอนนี้ โดยให้การ์ดจอคำนวณแทนซีพียู
(การเทรนข้อมูล 1.25 ล้านตำแหน่ง 20 superbatch ใช้เวลาประมาณ 2 วินาทีบน RTX 4060) ขั้นตอนอื่นและ ESP32 ไม่ใช้ CUDA

### ขั้นที่ 4 — ใส่ net เข้า engine แล้วแข่งทดสอบ

engine โหลด net ผ่านคำสั่ง UCI:

```text
setoption name EvalFile value checkpoints/wyrd-20/quantised.bin
setoption name Nodes value 20000
```

จากนั้นนำ engine ที่ใช้ net ใหม่ไปแข่งกับ engine เดิม **หลายร้อยเกม** ด้วยโปรแกรมแข่ง
(`fastchess` หรือ `cutechess-cli`) และพิจารณาผล Elo ขั้นตอนและพารามิเตอร์ทั้งหมดอยู่ใน [EVALUATION.md](EVALUATION.md)

> **กฎของโครงการ:** net ใหม่จะถูกรับก็ต่อเมื่อชนะ **เกินช่วงความคลาดเคลื่อน**
> ค่า loss ที่ต่ำลงอย่างเดียวไม่เป็นหลักฐาน (net อาจเพียงจดจำข้อมูล หรือข้อมูลอาจง่ายเกินไป)

### ขั้นที่ 5 — วนซ้ำ

หาก net ผ่านการแข่ง ให้ใช้ engine ที่ใช้ net นั้นสร้างข้อมูลรอบใหม่ (ระบุ `net.bin` ท้ายคำสั่ง datagen)
ซึ่งทำให้คะแนนในข้อมูลแม่นยำขึ้น จากนั้นเทรนและแข่งอีกครั้ง ทำซ้ำจนความแรงไม่เพิ่มขึ้นหรือถึงระดับที่ต้องการ

**ขีดจำกัดของวงวน:** ในที่สุดความแรงจะหยุดเพิ่ม โดยมีสาเหตุหลัก 3 ประการ
1. net เล็กเกินกว่าจะเรียนรู้เพิ่ม (เพดานขึ้นกับขนาด net ซึ่งถูกจำกัดด้วย RAM ของ ESP32)
2. ข้อมูลที่ engine สร้างเองไม่มีสิ่งใหม่ให้เรียน
3. เทรนซ้ำกับชุดข้อมูลเดิมจน net จดจำแทนที่จะสรุปความรู้

สำหรับเป้าหมาย "ไม่แรงแต่ฉลาด" การถึงขีดจำกัดไม่ใช่ปัญหา เพียงหยุดเมื่อถึงระดับที่ต้องการ
แล้วควบคุมความแรงด้วยจำนวน node ขณะเล่น

### ขั้นที่ 6 — ฝังลง ESP32 (ยังไม่ได้ดำเนินการ)

แยกส่วนอ่าน net และคำนวณเป็นโค้ด `no_std` ที่ใช้ int16/int8 ทดสอบบนพีซีก่อนว่าผลตรงกับ
เวอร์ชันบน PC ทุกตำแหน่ง จึงนำลงบอร์ด และฝัง net ด้วย `include_bytes!` ดู [ROADMAP.md](ROADMAP.md)

## 4. คำถามที่พบบ่อย

**bullet เล่นหมากรุกเองหรือไม่?** ไม่ bullet เพียงอ่านข้อมูลและปรับน้ำหนัก ผู้เล่นคือ engine ของโครงการ

**net รู้กฎหมากรุกหรือไม่?** ไม่ กฎอยู่ใน `cozy-chess` net รู้เพียงว่าตำแหน่งลักษณะใดมักดีหรือไม่ดี

**net เลือกตาเดินให้โดยตรงหรือไม่?** ไม่ net ให้คะแนนตำแหน่งเท่านั้น การค้นหา alpha-beta
ลองตาเดินหลายทางและเลือกทางที่ net ให้คะแนนตำแหน่งปลายทางดีที่สุด

**เหตุใดจึงสุ่มเปิดเกม?** เพื่อให้แต่ละเกมแตกต่างกัน แต่ตำแหน่งที่ได้จากการสุ่มอาจไม่เหมือนเกมจริง
ผลกระทบต่อความแรงยังไม่ได้ทดสอบ (สามารถทดลองเทียบกับ opening book ได้ เพราะการเทรนใช้เวลาสั้น)

**เหตุใดผลเสมอจึงสูงประมาณ 80%?** สันนิษฐานว่า engine รอบแรกประเมินเพียงมูลค่าหมาก จึงรุกฆาตได้ไม่ดี
และเกมที่เดินครบ 300 ตาถูกนับเป็นเสมอ (ยังไม่ได้วัดสัดส่วนของแต่ละสาเหตุ) ข้อมูลรอบถัดไปควรดีขึ้นเมื่อ engine ใช้ net

**ควรเทรนกี่รอบ?** ไม่มีตัวเลขตายตัว พิจารณาจากผลแข่ง A/B ของแต่ละรอบ

## 5. ข้อมูลที่ต้องบันทึกทุกครั้งที่ได้ net ใหม่

เพื่อให้สร้างซ้ำได้ (กฎเหล็กข้อ 1 ใน `CLAUDE.md`) ต้องบันทึกรายการต่อไปนี้ใน `nets/RECORDS.md`:

- git commit hash ของโค้ดตอนเทรน และ rev ของ bullet
- ค่าที่ใช้กับ trainer (superbatches, batches_per_sb, batch_size, wdl, net_id)
- ข้อมูลที่ใช้ (seed, nodes, จำนวนเกม, ใช้ net ตัวไหนสร้างข้อมูล)
- ผลแข่งเทียบกับตัวก่อนหน้า (จำนวนเกม, Elo ± ความคลาดเคลื่อน)
